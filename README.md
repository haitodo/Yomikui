# Yomikui

X (Twitter) 向けの複数カラム型ダッシュボード拡張機能です。Manifest V3 に対応しています。

開発・確認には Node.js と `package.json` に指定された pnpm を使用します。

```powershell
pnpm test
pnpm build
```

ビルド結果は `dist/` に出力されます。Chrome / Edge の拡張機能管理画面で
開発者モードを有効にし、`dist/` を「展開して読み込み」で指定してください。
更新後は拡張機能と開いているダッシュボードを再読み込みします。

各列のヘッダーにある家のアイコン「この列の初期ページに戻る」で、履歴をたどらずに
列に設定したページへ戻れます。検索列は検索画面、ホーム列はホーム、URL指定列は設定したURLを開きます。
「最後に開いていたページを記憶」が有効でも、移動先とタブの記憶を消してから戻るため、
更新直後に以前の移動先が復元されることはありません。記憶する設定自体は引き続き有効です。
履歴列・チャット列にはこのボタンを表示しません。
通常の「戻る」は引き続き1画面ずつ戻り、タイトルのクリックは一覧の先頭へ移動します。
列名は「検索 · 最新」「ホーム · おすすめ」のように元の種類を残し、独自の列名はそのまま表示します。
タブは選択したページと合わせて記憶し、別ページには適用しません。検索結果のタブはURLに従います。
各列のヘッダーにあるコピーアイコン「この列のURLをコピー」で、現在その列で開いているページのURLを
クリップボードにコピーできます。列内のリンクを辿って移動した先の投稿詳細やユーザープロフィールなどのURLも
そのまま取得でき、拡張機能固有の内部パラメータ（`yomikui` クエリや内部ハッシュ）は自動的に除外されたURLがコピーされます。
コピー完了時はアイコンがチェックマークへ一時的に変化します。
この共通処理は `columnNavigation.js` で管理しています。
また、複数列表示時のマウス操作では、マウスカーソルが列の上に入った際にその列を自動的にアクティブ（フォーカス）にする追従機能を備えています。これにより、直前に別の列をクリックしていた場合でも、マウスの戻るボタン（サイドボタン）を押した際にカーソルが乗っている列が意図通り1画面戻ります。列ヘッダー上で戻るボタンが押された場合も親ダッシュボード全体の意図しないページバックを防ぎ、その列を戻します。返信欄や検索ボックスなどのテキスト入力中やドラッグ操作中はフォーカス追従を自動的に抑止し、タイピングや操作の中断を防ぎます。

列設定の「列幅」で「自動で均等」と「固定幅」を選べます。自動幅の列は、
固定幅の列を除いた残りの領域を均等に使い、20rem未満になる場合は横スクロールします。
固定幅はスライダー、または数値入力（20〜80rem、Enterまたはフォーカスを外すと確定）で指定します。
自動幅に切り替えても以前の固定幅は保持されます。既存の列は固定幅のまま読み込まれます。
ワークスペースの管理メニューの「すべての列を均等にする」で一括切り替えでき、
自動幅の列があるワークスペースに追加する列も自動幅になります。
4Kモニター等の広い画面で列幅を広げた際（36rem / 576px以上）、タイムライン内の単体画像・動画はX本来の600px幅や510px高さ制限を自動解除し、黒帯を作らず列幅いっぱいに拡大表示します。複数枚画像（2〜4枚）は2列や2×2のグリッド配置を保ちつつ4:3比率で列幅全体へ拡大し、縦トリミングを大幅に抑制します。またワイド列では表示ボケを防ぐため画像URLを自動で `name=large`（長辺最大2048px）へ昇格します。
列幅のルールと設定UIは `columnLayout.js`、メディアの拡大表示と解像度昇格は `wideMedia.js` で管理しています。

サイドバーまたは拡大ビューアの「メディアPiP」ボタンで、画像と動画を表示できる最前面ウィンドウを開きます。
開いている間は、どの列で画像を選んだり動画の再生を押したりしても、同じウィンドウで切り替わります。
複数枚の画像はPiPの前後ボタンで送れます。PiPを閉じると、次の選択から通常の表示に戻ります。
Document Picture-in-Picture APIに対応するブラウザーで利用できます。

列設定の「ツイート表示」では、「引用リツイート一覧ボタンを表示」「リツイート一覧ボタンを表示」
「表示（/analytics）を非表示」「共有ボタンを非表示」を個別に切り替えられます。
一覧ボタンはツイート下部に追加され、そのツイートの `/quotes`・`/retweets` を同じ列で開きます。
Ctrl / Cmd + クリックでは新しいタブで開けます。既存のリツイート操作はそのまま使えます。
設定は列ごとに保存されます。
「表示」「共有」は初期状態で非表示、一覧ボタンの表示は初期状態でオンです。保存済みの設定は保持されます。
一覧ボタンには、それぞれの件数が1件以上ある場合だけアイコンの右に件数を表示します。
0件または件数を取得できていない場合はアイコンだけを表示します。
件数は取得済みのツイートデータとXの表示から読み取り、追加の通信は行いません。
履歴列・チャット列ではこれらの設定は利用できません。
設定UIと一覧ボタンの共通処理は `tweetActions.js` で管理しています。

列設定の「一般」にある「リンクの表示先の列」では、その列で開いたX内リンクを表示する先の列を選べます。
特定の列（例：「3列目: 検索」）や「右隣の列」を指定でき、2列目→3列目、3列目→4列目のように連鎖させることもできます。
ツイート詳細、引用・リツイート一覧、ユーザープロフィール（リツイート一覧等のユーザー行を含む）、ハッシュタグ、リストなどのX内ページ遷移が指定先の列で開きます。
ユーザー名やアバター、メンションなどをクリックした際は、通常ポストのみの画面ではなく、リツイートも含めたすべての投稿が表示される `https://x.com/ユーザーID/all` がデフォルトで開きます（同一列での通常遷移・別列ルーティング・中クリックや新規タブ遷移に対応。プロフィールページ内の「ポスト」「返信」等の手動タブ切り替えは妨げません）。
これにより、元のタイムラインや一覧の表示位置をそのまま維持したまま、詳細やユーザー情報を別の列で確認できます。
表示先の列が画面内に完全に見えているときは横スクロールせず、画面外にあるときだけその列が見える位置まで自動で横スクロールし、一時的に強調枠を表示します。
表示先の列で返信などの入力を行っている最中は下書き保護のため振り分けを行わず、クリックした列で開きます。
タブ切り替え（「おすすめ／フォロー中」「ポスト／返信／メディア」等）、いいね・リポスト・フォロー等のボタン操作、画像の拡大表示、外部サイトリンク、Ctrl / Cmd / Shift + クリックや中クリックは通常どおり動作します。
履歴列・チャット列・Grok列・ポスト作成列ではこの設定は利用できません。Live Feed列は送り元として利用できます。
この振り分け処理と設定UIは `tweetRouting.js` で管理しています。

サイドバー下部には現在使用しているXアカウントのアバターアイコンが常時表示されます。
ワークスペースアイコンと同様にサイドバー上で直感的にログインアカウントを把握でき、
ホバー時には表示名とユーザー名（@ユーザー名）がツールチップで表示されます。
アイコンをクリックすると、設定画面を開くことなくサイドバーから直接Xのアカウント切り替えメニューが開き、
別のアカウントへ素早く切り替えられます。設定画面内でも現在のアカウント情報がプレビュー表示されます。
このアカウント情報検出・同期処理は `columnNavigation.js` で管理しています。

監視処理は次のファイルで管理しています。

- `frameMaintenance.js`: カラム内のツイート件数、重複要素の整理、更新推奨の判定。
  ツイート件数は DOM の変更を最大4秒でまとめて処理し、件数が変わったときだけ通知します。
  非表示カラム・タブでは監視とタイマーを解除し、再表示時に再開します。
  FPS はセッションが10分以上かつ DOM 更新が多い場合に限り、1秒間ずつ計測します。
- `downloadManager.js`: ダウンロードの状態管理と進捗通知。
  ポーリングの完了後に次の監視を予約し、重複実行を防ぎます。
  変更のあるバッチだけをまとめて通知し、完了・失敗後5秒で追跡データを解放します。
- `mediaInterceptor.js`: iframe 内のメディアレスポンス取得。
- `wideMedia.js`: ワイド列に応じたXタイムライン・メディアのサイズ制限解除と、高解像度画像（name=large）への自動昇格。

`contentIframe.js` は既存のバンドルです。カラム監視は先に読み込まれる
`frameMaintenance.js` を利用し、バックグラウンドは ES モジュールとして
`downloadManager.js` を読み込みます。追加の実行時依存パッケージはありません。

フローティングパネルの「選択中の列を更新」で、選択範囲内にあるホームの
「おすすめ」「フォロー中」、「検索結果」、「話題を検索（Explore）」を1列ずつ更新できます。
スクロールと同じ対象選択と画面内の列を使い、現在のページとタブから判定します。
列の作成時の種類にかかわらず、ホームの「おすすめ」「フォロー中」、検索結果、Exploreを
現在表示している列が対象になります。
画面外の列は起動・更新しません。ホームでは新着の「○件のポスト表示」があればそれを押し、
なければ選択中の「おすすめ」または「フォロー中」タブを1回だけ押します。
ただし、累計ツイート数が200件以上で負荷の警告が出ている列は、その列のiframeを丸ごと再読み込みします。
累計件数と警告をリセットし、現在のページ・選択中のタブを維持して先頭を表示します。
タブバーを非表示にする設定でも、XのタブがDOMに残っていれば動作します。
Exploreの「話題を検索」「トレンド」「ニュース」「スポーツ」「エンターテイメント」などは、
現在のURL・タブを保ったまま、その列のiframeだけを再読み込みして先頭を表示します。
検索結果も同じ方法で更新し、検索語・「話題のポスト」「最新」「アカウント」「メディア」「リスト」などの
タブ・絞り込み条件を維持します。「フォロー中 – 最新（時系列）」の列も検索結果として更新できます。
列の初期ページや「最後に開いていたページを記憶」の設定によらず、現在の表示先を維持します。
投稿詳細を表示中の列、入力中の列は更新しません。
更新前には、各列を手動の「先頭」と同じ即時スクロールで先頭へ戻します。
200ms以上の待機と2回以上の描画フレームで先頭への到達を確認してから、更新操作へ進みます。
1.2秒以内に確認できない列は「先頭への移動を確認できませんでした」としてスキップします。
準備中にページ・タブ・表示範囲が変わった場合も更新を実行しません。

この機能は `homeRefresh.js` で管理し、Xの画面操作だけを使います。タイムラインAPIの
直接呼び出し、タブの往復、ダッシュボード全体の再読み込み、自動更新や更新操作の自動再試行は
追加しません。連打を防ぐため完了後5秒間は次の一括更新を待機します。
ワークスペースの切り替え、タブの非表示、画像の拡大表示などで処理を中止します。
投稿一覧の変化を確認できない場合は「操作済み・表示変化未確認」と表示します。
再読み込みでは現在のタブと一覧表示を確認してから次の列へ進みます。検索結果が0件の場合も
結果表示を確認します。結果は「再読み込み」と
表示し、投稿が変化したという意味の「表示更新」とは区別します。表示を確認できなければ
「再読み込み操作済み・表示未確認」と表示します。確認用の情報は列ごとの一時領域に保存し、
再読み込み後に取り除きます。古い情報から更新を再実行することはありません。
更新ボタンにマウスを重ねると、列ごとの結果を確認できます。

フローティングパネルで更新すると、更新直前の先頭投稿にアンバーの区切り線と
「更新前の先頭」を表示します。先頭へ戻った後、実際の更新操作の直前に投稿を記憶するため、
途中までスクロールしていても、更新前の一覧の先頭が目印になります。
目印は列ごとに最新の1件だけ保持し、通常のホーム更新と、検索結果などの列全体の
再読み込みに対応します。元の投稿がスクロール先で読み込まれた場合も表示します。
投稿が削除された場合や更新後の一覧に含まれない場合は、別の投稿に目印を付けません。
投稿がない検索結果やトレンド項目だけの一覧には表示しません。ページ・タブを変えると目印を解除します。
「おすすめ」などでは投稿が並び替わるため、目印は既読・未読を正確に分けるものではありません。
表示は投稿の高さを変えず、追加通信やスクロール位置の計算も行いません。
`refreshBoundary.js` が投稿要素の差し替えを80ms単位でまとめて確認し、
非表示の列・タブでは監視とタイマーを解除します。

閲覧・更新の操作は1つのフローティングパネルにまとまっています。初期位置は右下で、
ヘッダーをドラッグすると画面内の好きな場所に移動できます。ヘッダーにフォーカスして
矢印キーでも移動できます。位置・移動方式・背景色・透明度はブラウザーごとに保存し、
再読み込み後も復元します。画面サイズを変更した場合は画面内に収まるよう補正します。
対象の種類ボタンは常時表示し、その直下の1行に先頭・上下移動・更新を並べています。
歯車から開く設定に「投稿ごと／画面ごと」、背景色、透明度をまとめています。
配色と角丸は既存UIに揃え、ダーク・ディム・ライトのテーマに追従します。
展開した設定の「背景色」で、ブルーグレー（標準）・ラベンダー・セージ・グレー・テーマ色から選べます。
パネル全体に淡い色を付け、各テーマに合わせて明るさを切り替えます。先頭・上・下のボタンは同じ配色です。
展開した設定の「透明度」で、背景を0〜80%（5%刻み）まで透かせます。0%は不透明です。
文字・アイコンはくっきり表示し、背景色・透明度の変更はその場で反映します。
更新結果は更新ボタン内に一時表示し、説明行や結果表示のための余白は設けません。
表示更新・再読み込みを確認できた場合は「完了」、確認できない場合は「未確認」、
スキップだけの場合は「対象外」、一部スキップした場合は「一部」と表示します。
処理中は更新ボタンが「中止」になり、残りの更新を中止できます。
更新中の再読み込みによって種類の判定が一時的に途切れても、対象ボタンの配置は保ちます。

対象は「おすすめ」「フォロー中」「検索結果」「話題を検索」の種類単位で選べます。
「切り替え」は押した種類だけを選び、「複数選択」は種類を追加・解除します。
それぞれの選択内容はワークスペースごとに記憶し、複数の種類に該当する範囲も各列1回ずつ操作します。
初期状態は「おすすめ」です。以前の「表示中すべて」は4種類の複数選択へ移行し、
以前の種類別選択はその種類を復元します。廃止した個別列指定は初期状態へ移行します。
種類別の対象は、列の作成時の種類ではなく、現在表示しているページ・タブから判定します。
例えば「おすすめ」を選ぶと、検索結果やフォロー中の列を動かさず、おすすめの列だけを移動します。
画面内の列数は種類ボタン内だけに表示します。「0列を隠す」は初期状態でオンです。
非表示になった種類も選択状態を保持し、再び画面内に列が現れたら同じ選択を使います。
この表示設定はブラウザーごとに保存します。
対象が0列なら移動ボタンを無効にし、別の対象へ自動では切り替えません。
「上へ」「下へ」「先頭へ」で同じ対象を使い、
画面内に見えている通常のXタイムライン列だけを移動し、画面外の列を起動・移動しません。
「投稿ごと」は前後の投稿の先頭へ移動し、長い投稿は画面の約8割ずつ進めます。
「画面ごと」は常に画面の約8割ずつ移動します。フォロー中にも対応します。
Exploreでは「投稿ごと」でニュースやトレンドの項目へ移動でき、ホイール・画面ごと・先頭にも対応します。
パネル上でホイールやトラックパッドを上下にスクロールすると、同じ対象の列を入力した量に応じて移動できます。
最初の入力は描画待ちをせずに送り、同じ描画フレーム内の追加入力だけをまとめます。移動量の制限はブラウザーのスクロール処理に任せ、投稿位置の計算を省いています。
プルダウン・透明度スライダー上の操作、修飾キーを押しながらの操作、横方向の操作は通常の動作を優先します。
画面が小さくパネル自体を縦にスクロールする必要がある場合も、パネル内の操作を優先します。
「先頭へ」は同じ対象設定に従って、選択した列の一覧の一番上へすぐに戻ります。
新着の更新操作は行わず、移動方式の「投稿ごと」「画面ごと」にも影響しません。
履歴・チャット・投稿詳細・入力中・ダイアログ表示中などは対象外です。
更新中は閲覧ボタンを無効にし、クリックの連続実行を予約する処理や自動スクロールは追加しません。
更新も同じ対象選択に従い、その範囲で現在ホームの「おすすめ」「フォロー中」、検索結果、Exploreを
表示している列を1列ずつ処理します。更新ボタンにマウスを重ねると種類ごとの対象列数と更新方法を確認できます。
選択範囲に更新対象がない場合や対象を復元中の場合は更新ボタンを無効にし、別の列へ自動では切り替えません。
列の追加時の種類や記憶したタブ名だけで判定せず、操作の直前にも表示内容と表示範囲を確認します。
閲覧からAPIを直接呼び出す処理はありませんが、下端付近ではX本来の追加読み込みが発生する場合があります。
パネルと閲覧リクエストは `floatingControls.js`、列内の移動は `homeScroll.js` で管理しています。
パネルのCSSは、ダッシュボードによるスタイル整理で削除されないよう、既存の
`yomikui-styles` にまとめて追加します。

通常のホーム列では、列設定の「フィード → おすすめの新着読み込み後の表示位置」で
「新着の先頭を表示（標準）」と「既存投稿の位置を保持」を選べます。初期値は標準で、
既存の列にも適用されます。位置を保持する場合は、表示中の投稿を基準に復元します。
この設定は一括更新とXの新着表示操作に適用し、フォロー中には適用しません。
`homeScroll.js` が更新中だけ位置を追跡し、ユーザーがスクロールなどを操作したら調整を止めます。
Xの仕様変更によって操作できなくなる可能性があり、画面操作であっても
利用制限やアカウント凍結のリスクがなくなることを保証するものではありません。

`tests/` のテストは Node.js 標準のテストランナーを使用し、ブラウザー API と
時計を模擬して非表示・再表示、DOM ノードの再利用、同時ダウンロード、
遅い API 応答、完了後の解放を確認します。実ブラウザーの CPU・メモリ使用量の
測定は含みません。
