# Yomikui

X (Twitter) 向けの複数カラム型ダッシュボード拡張機能です。Manifest V3 に対応しています。

開発・確認には Node.js と `package.json` に指定された pnpm を使用します。

```powershell
pnpm test
pnpm build
```

ビルド結果は `dist/` に出力されます。Chrome / Edge の拡張機能管理画面で
開発者モードを有効にし、`dist/` を「展開して読み込み」で指定してください。
更新後は拡張機能と開いているダッシュボードを再読み込みします。

列設定の「列幅」で「自動で均等」と「固定幅」を選べます。自動幅の列は、
固定幅の列を除いた残りの領域を均等に使い、20rem未満になる場合は横スクロールします。
固定幅はスライダー、または数値入力（20〜45rem、Enterまたはフォーカスを外すと確定）で指定します。
自動幅に切り替えても以前の固定幅は保持されます。既存の列は固定幅のまま読み込まれます。
ワークスペースの管理メニューの「すべての列を均等にする」で一括切り替えでき、
自動幅の列があるワークスペースに追加する列も自動幅になります。
列幅のルールと設定UIは、`contentDeck.js` より先に読み込む `columnLayout.js` で管理しています。

列設定の「ツイート表示」では、「引用リツイート一覧ボタンを表示」「リツイート一覧ボタンを表示」
「表示（/analytics）を非表示」「共有ボタンを非表示」を個別に切り替えられます。
一覧ボタンはツイート下部に追加され、そのツイートの `/quotes`・`/retweets` を同じ列で開きます。
Ctrl / Cmd + クリックでは新しいタブで開けます。既存のリツイート操作はそのまま使えます。
通常のX表示とLive Feedに対応し、設定は列ごとに保存されます。
「表示」「共有」は初期状態で非表示、一覧ボタンの表示は初期状態でオフです。保存済みの設定は保持されます。
一覧ボタンには、それぞれの件数が1件以上ある場合だけアイコンの右に件数を表示します。
0件または件数を取得できていない場合はアイコンだけを表示します。
件数は取得済みのツイートデータとXの表示から読み取り、追加の通信は行いません。
Live Feedには元から共有ボタンがありません。履歴列・チャット列ではこれらの設定は利用できません。
設定UIと一覧ボタンの共通処理は `tweetActions.js` で管理しています。

監視処理は次のファイルで管理しています。

- `frameMaintenance.js`: カラム内のツイート件数、重複要素の整理、更新推奨の判定。
  ツイート件数は DOM の変更を最大4秒でまとめて処理し、件数が変わったときだけ通知します。
  非表示カラム・タブでは監視とタイマーを解除し、再表示時に再開します。
  FPS はセッションが10分以上かつ DOM 更新が多い場合に限り、1秒間ずつ計測します。
- `downloadManager.js`: ダウンロードの状態管理と進捗通知。
  ポーリングの完了後に次の監視を予約し、重複実行を防ぎます。
  変更のあるバッチだけをまとめて通知し、完了・失敗後5秒で追跡データを解放します。
- `mediaInterceptor.js`: iframe 内のメディアレスポンス取得。
  Live Feed では本文の複製・読み出し・JSON 文字列化を省きます。
- `xTransactionBridge.js`: ブックマーク操作に必要な X の初期データを退避。
  DOM 更新時は変更された部分だけを調べます。

`contentIframe.js` は既存のバンドルです。カラム監視は先に読み込まれる
`frameMaintenance.js` を利用し、バックグラウンドは ES モジュールとして
`downloadManager.js` を読み込みます。追加の実行時依存パッケージはありません。

通常のホーム列があるワークスペースでは、フローティングパネルの「ホームを一括更新」で
「おすすめ」を一括更新できます。横スクロールで画面外にある列も、必要に応じて
一時的に読み込んで1列ずつ処理します。新着の「○件のポスト表示」があればそれを押し、
なければ選択中の「おすすめ」タブを1回だけ押します。タブバーを非表示にする設定でも、
XのタブがDOMに残っていれば動作します。「フォロー中」など別のタブを表示中の列、
投稿詳細を表示中の列、入力中の列、Live Feedは更新しません。

この機能は `homeRefresh.js` で管理し、Xの画面操作だけを使います。タイムラインAPIの
直接呼び出し、タブの往復、ページ全体の再読み込み、自動更新や更新操作の自動再試行は
追加しません。連打を防ぐため完了後5秒間は次の一括更新を待機します。
ワークスペースの切り替え、タブの非表示、画像の拡大表示などで処理を中止します。
投稿一覧の変化を確認できない場合は「操作済み・表示変化未確認」と表示します。
結果にマウスを重ねると、列ごとの結果を確認できます。

閲覧・更新の操作は1つのフローティングパネルにまとまっています。初期位置は右下で、
ヘッダーをドラッグすると画面内の好きな場所に移動できます。ヘッダーにフォーカスして
矢印キーでも移動できます。位置・折りたたみ状態・移動方式はブラウザーごとに保存し、
再読み込み後も復元します。画面サイズを変更した場合は画面内に収まるよう補正します。
右上で設定部分を折りたたんでも、上下移動と更新のボタンは引き続き使えます。

「閲覧する列」は「表示中すべて」、または特定の1列を選べます。「上へ」「下へ」で、
画面内に見えている通常のXタイムライン列だけを移動し、画面外の列を起動・移動しません。
「投稿ごと」は前後の投稿の先頭へ移動し、長い投稿は画面の約8割ずつ進めます。
「画面ごと」は常に画面の約8割ずつ移動します。フォロー中にも対応します。
Live Feed・履歴・チャット・投稿詳細・入力中・ダイアログ表示中などは対象外です。
更新中は閲覧ボタンを無効にし、クリックの連続実行を予約する処理や自動スクロールは追加しません。
閲覧する列の選択は一括更新の対象には影響せず、更新はこれまでどおりホーム列全体を1列ずつ処理します。
閲覧からAPIを直接呼び出す処理はありませんが、下端付近ではX本来の追加読み込みが発生する場合があります。
パネルと閲覧リクエストは `floatingControls.js`、列内の移動は `homeScroll.js` で管理しています。
パネルのCSSは、ダッシュボードによるスタイル整理で削除されないよう、既存の
`yomikui-styles` にまとめて追加します。

通常のホーム列では、列設定の「フィード → おすすめの新着読み込み後の表示位置」で
「新着の先頭を表示（標準）」と「既存投稿の位置を保持」を選べます。初期値は標準で、
既存の列にも適用されます。位置を保持する場合は、表示中の投稿を基準に復元します。
この設定は一括更新とXの新着表示操作に適用し、フォロー中やLive Feedには適用しません。
`homeScroll.js` が更新中だけ位置を追跡し、ユーザーがスクロールなどを操作したら調整を止めます。
Xの仕様変更によって操作できなくなる可能性があり、画面操作であっても
利用制限やアカウント凍結のリスクがなくなることを保証するものではありません。

`tests/` のテストは Node.js 標準のテストランナーを使用し、ブラウザー API と
時計を模擬して非表示・再表示、DOM ノードの再利用、同時ダウンロード、
遅い API 応答、完了後の解放を確認します。実ブラウザーの CPU・メモリ使用量の
測定は含みません。
